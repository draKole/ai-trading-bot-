# Charting and TradingView licensing assessment

## Decision

No TradingView Advanced Charts integration is included. The repository has no owner-provided TradingView library distribution, license key, or authorized vendor asset location. We must not download, vendor, or commit a third-party/redistributable TradingView bundle. The team should request the owner's authorized official library access before reconsidering integration.

## Supported alternative

The existing `frontend/src/pages/Charts.tsx` uses the already-declared `lightweight-charts` dependency (`frontend/package.json`) and the platform's own market-data API (`frontend/src/api/market-data.ts`). This is an independently supported chart surface and does not embed the TradingView widget or Advanced Charts library.

Current supported behavior includes:

- Candlestick and volume rendering with OHLCV crosshair
- 1m, 3m, 5m, 15m, 30m, 1H, 4H, and Daily selectors
- Date/session filtering, including explicit July 1–31, 2026 selection through the From/To controls
- EMA, VWAP, session/prior-period levels, FVG/order-block/liquidity/structure/SMT overlays
- Drawing tools and bounded five-second refresh polling

The chart requests bars from `/api/v1/market-data/bars` through the existing client. If July data is not present in the database, the UI intentionally displays the no-bars state; no synthetic market data is generated by the chart.

## July 1–31, 2026 verification boundary

The UI can request `2026-07-01T00:00:00` through `2026-07-31T23:59:59` for ES, MES, NQ, and MNQ at each supported timeframe. Actual display verification requires those historical rows to be imported through the authorized market-data workflow first. No July dataset or broker/vendor credentials are present in this repository, so this assessment does not claim that July bars are available.

## Validation

`npm run build` passes on the existing frontend. No TradingView assets were added, and no direct TradingView integration is claimed.
